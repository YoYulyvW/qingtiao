## 二、致命问题（必须修复）

### 致命1：AppDatabase 缺失 v1→v2、v2→v3 迁移 → 老用户数据丢失
位置：app/src/main/java/com/autoskip/helper/data/AppDatabase.kt:10-77
证据：
- @Database(version = 5, ...)
- .addMigrations(MIGRATION_3_4, MIGRATION_4_5)  // 只有 3→4、4→5
- .fallbackToDestructiveMigration()
问题：无 v1→v2、v2→v3。停留在 v1/v2 的用户升级后 Room 找不到路径 → 清空数据库。
证伪：代码存在 migrateV2IfNeeded / migrateV3IfNeeded → 历史确有 v2/v3 时期 → 老用户真实存在 → 结论成立。
修复：补全迁移 或 移除 fallbackToDestructiveMigration()。

### 致命2：激活并发超限（Check-Then-Act 竞态，无事务）
位置：111/internal/license/service.go:120-136
证据：先 SELECT COUNT 判断再 INSERT，中间无事务。
问题：maxDevices=1 的码，两台设备同时激活都读到 count=0 → 都通过。
证伪：database/sql SetMaxOpenConns(4) 允许多连接 → 两个 SELECT 可同时通过 → 结论成立。
修复：用事务包裹。

## 三、严重问题（12 项）

### 严重1：App.kt 迁移协程并发执行（App.kt:25-33）
5 个迁移/种子协程并发 → 互相读旧快照，结果不确定。
修复：串行化到一个协程。

### 严重2：JSON 手拼未转义控制字符（2 处）
位置：license/LicenseClient.kt:148-149、service/PushNotifier.kt:99-101
只转义反斜杠和双引号。用户输入含换行/制表符 → 非法 JSON。
修复：补齐 \n \r \t 及控制字符。

### 严重3：LicenseClient.post 无 finally 保证 disconnect（LicenseClient.kt:90-113）
readText() 抛异常时 disconnect 被跳过 → 连接泄漏。
修复：try/finally。

### 严重4：LicensePrefs.setBaseUrl 死参数（LicensePrefs.kt:30）
形参 v 未使用，直接写 DEFAULT_BASE。
修复：删除或改为 it[KEY_BASE] = v。

### 严重5：规则版本比较用 != 而非 >（LicenseManager.kt:82）
服务端 version 回退时触发无意义全量拉取。
修复：改 >。

### 严重6：管理后台密码用 SHA256 + 固定前缀（admin/api.go:40-43）
证据：sha256(\"kfhelper-admin:\" + p)
问题：固定前缀不是 salt；SHA256 无慢化 → 弱密码秒破。
证伪：admin 挂 /admin + push.lyvw.eu.org 暴露公网 → 结论成立。
修复：改 bcrypt。

### 严重7：管理后台登录无速率限制（admin/api.go:103-128）
handleLogin 失败直接 return，无限次尝试。
修复：失败计数 + 指数退避 + 锁定。

### 严重8：ProGuard 未启用混淆（build.gradle.kts:40）
证据：isMinifyEnabled = false；proguard-rules.pro 只 1 行。
问题：授权逻辑可被 jadx 反编译 patch。
修复：启用混淆 + 补充保留规则。

### 严重9：HTTP handler 同步调 TTS，阻塞请求（main.go:452-454）
证据：server.go:110 OnNotify 同步调用 → onNotify 内 speaker.SpeakNotice 同步。
Edge TTS 联网数百毫秒~秒级 → 手机端请求迟迟不返回。
修复：TTS 改异步 go func()。

### 严重10：部分 admin 接口未校验 HTTP Method（admin/api.go）
未校验：handleLogout（130）/ handleDeviceBlock（171）/ handleDeviceName（187）/ handleDeviceUnbind（203）/ handleCodeUpdate（248）/ handleCodeDisable（267）/ handleCodeDelete（283）
问题：GET 请求可触发状态变更 → CSRF 风险。
修复：统一加 Method 校验。

### 严重11【新】：settings_ui.go handleSave 直接 Unmarshal 到全局 config 指针
位置：111/internal/tray/settings_ui.go:108-112
证据：
- cfg := config.Get()  // 返回全局 current 指针
- json.Unmarshal(raw, cfg)  // 直接修改全局对象
- config.Save(cfg)
问题：
1. **并发不安全**：config.Get() 返回共享指针，无锁直接写入；同时 onNotify 等 goroutine 读 cfg → 数据竞争
2. **部分失败半更新**：json.Unmarshal 中途失败 → 全局 config 处于半更新状态 → 正在跑的隧道/推送读到脏配置
3. **未生效即污染**：即使 Save 失败，内存中的 config 已被污染
修复：
- cfg := config.Default(); json.Unmarshal(raw, cfg); 校验成功后加锁替换全局
- 或 config.Save() 内部做「先解析到临时对象，成功后原子替换」

### 严重12【新】：settings_ui.go 部分接口无 Method 校验
位置：111/internal/tray/settings_ui.go
未校验：handleConfig（86）/ handleLogs（123）/ handleSysLog（176）/ handleTest（271）
问题：虽只读，但不规范；若未来扩展为写操作易出坑。
注：settings 页只监听 127.0.0.1（安全兜底），故风险等级低于严重10。
修复：统一加 Method 校验。
