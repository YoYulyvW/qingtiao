# 云端规则管理需求文档

> 日期：2026-10-02
> 范围：客户端（Android）接口对接 + Web 管理后台页面
> 目标：内置规则云端化，服务端可增删改，客户端同步且保留用户本地状态

---

## 一、设计目标

| 目标 | 说明 |
|---|---|
| 内置规则云端化 | 8 条普通 + 5 条条件规则的初始内容放服务端，可远程更新 |
| 首装可用 | 客户端硬编码兜底，无网也能用 |
| 用户改动独立 | 用户改内容 → 转 user，完全脱离云端管控 |
| 本地启用状态保留 | 云端更新时**不覆盖**用户本地的 enabled |
| 防止重复触发 | 云端去重 + 执行时去重（双保险） |

---

## 二、数据模型

### 2.1 serverId 约定（★核心）

内置规则使用**固定 serverId 段**，云端与客户端必须一致：

| 类型 | serverId 范围 | 数量 |
|---|---|---|
| 内置普通规则 | 1001 - 1099 | 8 |
| 内置条件规则 | 2001 - 2099 | 5 |
| 内置控件规则 | 3001 - 3099 | 0（预留）|
| 用户自建（服务端）| 10000+ | 服务端自增 |

### 2.2 规则 content 结构

```json
// 普通规则（type=rule）
{
  "name": "跳过",
  "text": "跳过",
  "exact": true,
  "packageName": null,
  "viewId": null
}

// 条件规则（type=cond）
{
  "name": "关注+作品/粉丝→返回",
  "hasText": "关注",
  "andText": "作品|粉丝",
  "actionType": "BACK",
  "actionText": null,
  "packageName": null,
  "delaySec": 2
}

// 控件规则（type=widget）
{
  "remark": "看全集",
  "widgetId": "vfd",
  "matchText": null,
  "actionType": "CLICK",
  "coordX": 0,
  "coordY": 0,
  "packageName": null
}
```

## 四、客户端接口需求

### 4.1 现有接口（已实现，无需改）

#### GET /rules/get
**作用**：客户端拉取全量规则

**请求**：
```json
POST /rules/get
Content-Type: application/json

{
  "deviceId": "<ANDROID_ID>"
}
```

**响应**：
```json
{
  "ok": true,
  "version": 42,
  "rules": [
    {
      "serverId": 1001,
      "type": "rule",
      "content": { ... },
      "enabled": true,
      "targetCodes": []
    },
    ...
  ]
}
```

**要点**：
- `version` 为单调递增整数（规则表任一变更为 +1）
- `rules` 为全量数组（非增量）
- `targetCodes` 为空数组时对所有设备生效

---

#### POST /license/check
**作用**：心跳 + 携带 `rulesVersion`

**响应关键字段**：
```json
{
  "ok": true,
  "serverNow": 1759400000000,
  "rulesVersion": 42,
  "features": { ... }
}
```

**客户端逻辑**：
- 若 `rulesVersion > 本地版本` → 触发 `/rules/get` 同步

---

### 4.2 无需新增接口

客户端仅需 `/rules/get` 和 `/license/check` 的 `rulesVersion`。

## 五、客户端同步逻辑

### 5.1 RuleSync 合并规则（★关键）

```
对云端每条规则：
  1. serverId ≤ 0 → 跳过（非法）
  2. serverId 在墓碑中 → 跳过（用户删过）
  3. 查本地同 serverId 规则：
     a. 无 → 插入（enabled = 云端值）
     b. 有且 source = user → 跳过（用户改过，已脱离）
     c. 有且 source = server → 覆盖内容，保留本地 enabled

对本地所有 source=server 但云端已不存在的规则：
  4. 删除本地（除已转 user 的）
```

### 5.2 字段合并规则（云端覆盖时）

| 字段 | 取值来源 |
|---|---|
| hasText / andText / actionType / actionText / packageName / delaySec | **云端** |
| enabled | **本地**（保留用户禁用状态）|
| source | 保持 `server` |
| id | 保留本地 id（主键） |

### 5.3 内容去重（新增规则时）

云端下发**新增**规则（本地无此 serverId）时，先检查本地是否已有**内容等价**的规则：

**等价判定** = 以下四项全等（忽略 name 和 delaySec）：
- `hasText`
- `andText`（空值视为 ""）
- `actionType`
- `actionText`（空值视为 ""）

若有等价规则 → **跳过插入**（避免双条并发触发）。

### 5.4 执行时去重（★防重复触发）

`performCondAction` 执行前：

```kotlin
val contentKey = hasText + "|" + (andText ?: "") + "|" + actionType + "|" + (actionText ?: "")
val lastByContent = lastCondContentExec[contentKey] ?: 0L
if (now - lastByContent < 1000) return   // 等价内容 1 秒内不重复
lastCondContentExec[contentKey] = now
```

### 6.3 内容去重校验（★新增）

**新增/编辑条件规则时，服务端应校验**：

若 `hasText + andText + actionType + actionText` 与**已有规则**（同类型）等价：
- **新增** → 拒绝，提示"已存在等价规则"
- **编辑** → 允许（可能是修正）

**目的**：从源头减少重复规则。

### 6.4 内置规则特殊标记（★新增）

`serverId` 在 1001-1099 / 2001-2099 / 3001-3099 范围的，UI 标记「内置」：
- 列表用灰色徽章
- 删除时额外提示（可能影响存量用户）
- **不允许修改 serverId**（编辑时禁用）

### 6.5 目标激活码（targetCodes，可选）

当前 API 已有 `targetCodes` 字段（空数组 = 全部设备）。

**本次不强制做**，可在后续迭代加 UI（如多选激活码）。

## 七、服务端改动清单

### 7.1 启动 seed（★新增）

`license.Open()` 时，若 `server_rules` 表为空 → 插入 13 条内置规则（serverId 1001-1008 + 2001-2005）。

**注意**：
- 用 `INSERT OR IGNORE`（幂等）
- 只 seed 一次（表空才做）
- 若云端已删某内置规则 → 不重新 seed（避免死循环）

### 7.2 内容去重校验（★新增）

`CreateServerRule` 新增规则时，先查询同类型等价规则：

```go
SELECT COUNT(*) FROM server_rules
WHERE type = ?
  AND json_extract(content, '$.hasText') = ?
  AND COALESCE(json_extract(content, '$.andText'), '') = ?
  AND json_extract(content, '$.actionType') = ?
  AND COALESCE(json_extract(content, '$.actionText'), '') = ?
```

若 > 0 → 返回错误"已存在等价规则"。

**注意**：SQLite 的 `json_extract` 需 SQLite ≥ 3.38（modernc.org/sqlite 已支持）。

### 7.3 无需新增接口

现有 `/rules/get` 和 `/admin/api/rule/*` 已满足需求。

## 九、验收标准

### 客户端
- [ ] 首装：本地出现 13 条内置规则（带固定 serverId）
- [ ] 联网后：云端同 serverId 规则覆盖内容，enabled 保留本地
- [ ] 用户禁用规则 → 云端改内容 → 本地仍禁用
- [ ] 用户改内容 → 转 user → 云端改动不影响
- [ ] 云端删规则 → 本地删（除已转 user 的）
- [ ] 云端删内置规则 → 客户端不再 seed 回来
- [ ] 同一条件规则不会触发 2 次返回键

### Web 端
- [ ] 可新增/编辑/删除规则
- [ ] 新增等价规则被拒绝
- [ ] 内置规则显示「内置」标记
- [ ] 修改规则后，客户端 1 分钟内同步

## 十、实施顺序

1. **服务端**：启动 seed（13 条）+ 内容去重校验
2. **客户端**：seed 固定 serverId + RuleSync 保留 enabled + 执行时去重
3. **Web 端**：内置标记 + 新增时去重提示（可选，后端已校验）

## 附：边界说明

### A. 用户从云端规则「转 user」后
- 保留 serverId（不删）
- `source` 改为 `user`
- 云端后续改动/删除**均不影响**
- 本地墓碑不记录（因为规则还在）

### B. 用户删除云端规则
- 记录墓碑（serverId）
- 客户端本地删除
- 云端后续再下发同 serverId → 客户端检查墓碑 → 跳过

### C. 服务端「无网」时
- 客户端用本地缓存（含 seed 的 13 条）
- 心跳失败不影响使用（已有逻辑）

### D. 硬编码兜底的作用
- 首次安装 + 无网场景：本地仍有 13 条规则
- 一旦联网：云端同 serverId 覆盖（内容以云端为准）
